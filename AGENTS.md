# Mindes — правила работы с репозиторием

Этот файл — инструкция для агентов и разработчиков. Перед изменениями читайте исходный код и проверяйте команды по `package.json`: README содержит устаревшие формулировки. Рабочая ветка репозитория — `master`. Firebase-проект деплоя по умолчанию в `.firebaserc` — `mindes-15db2`; считайте его действующей средой, пока владелец проекта не подтвердит обратное.

## Что здесь находится

- Клиентское приложение на React 18 и Vite 5. Серверной части в репозитории нет.
- Веб-версия — PWA на Firebase Hosting; Android-версия — тот же веб-код в Capacitor 6.
- Вход через Google: на вебе Firebase Auth popup, на Android нативный плагин `@capacitor-firebase/authentication` с передачей ID token в Firebase JS SDK (`src/auth.js`).
- Данные — Cloud Firestore с локальным кешем (`src/firebase.js`, `src/sync.js`). Каждый проект хранится одним документом `users/{uid}/maps/{mapId}` с полным деревом задач и служебным `clientWriteId` для подтверждения записи; документ `users/{uid}` хранит `activeMapId` и настройки фона. Правила доступа — `firestore.rules`.
- Маршруты задаются вручную в `src/App.jsx`: `/`, `/archive`, `/immediate`, `/:projectId`, `/:projectId/:taskId`. Firebase Hosting переписывает маршруты на `index.html`.
- Основные экраны: `src/ProjectsHome.jsx` и `src/Mindmap.jsx`; операции с деревом и датами — `src/utils.js`; темы — `src/theme.js`; переводы — `src/i18n.jsx` (en, ru, zh, es, hi, pt, fr, kk).
- Приветственный экран `src/Login.jsx` доступен до входа и использует те же переводы. При первом открытии язык берётся из `navigator.language` (основной код языка браузера/устройства), если он поддерживается, иначе используется английский. Выбранный вручную язык хранится в `localStorage` под `mindes_locale` и имеет приоритет; страна и IP не определяют язык. Переключатель на приветственном экране должен работать без входа в аккаунт.
- Напоминания — `src/notifications.js`: на Android локальные уведомления, на вебе `Notification` и `setTimeout` только пока открыта вкладка (и не дальше максимума таймера примерно 24,8 суток). Здесь нет сервера Web Push.
- PWA service worker — `public/sw.js`, регистрация — `src/main.jsx`; в нативном приложении он не регистрируется. Офлайн-работа зависит от уже открытой/закешированной версии и прежней авторизации; первый вход требует сеть.

## Подготовка рабочего места

1. Нужны Git, Node.js и npm. Устанавливайте зависимости из зафиксированного `package-lock.json`: `npm ci`.
2. Создайте `.env.local` из `.env.example` и заполните все `VITE_FIREBASE_*` из **Firebase Console → Project settings → General → Your apps → Web app → SDK setup and configuration** для `mindes-15db2`. Проверяйте совпадение `projectId` с проектом, на который собираетесь выкладывать. Не коммитьте локальный файл. Префикс `VITE_` означает, что значения входят в публичный клиентский бандл: не кладите туда приватные ключи и токены.
3. Для запуска входа в Firebase Console должны быть включены **Authentication → Sign-in method → Google** и нужные **Authentication → Settings → Authorized domains** (в том числе локальный адрес при локальной проверке, если требуется). Доступ к Firestore должен соответствовать `firestore.rules`.
4. Для Android нужны Android Studio, Android SDK Platform 34, Build Tools 34, Gradle wrapper из `android/gradle/wrapper/gradle-wrapper.properties` и совместимый JDK. Проект использует Android Gradle Plugin 8.2.1 и Gradle 8.5; Gradle 8.5 поддерживает запуск на Java 21. В `android/gradle.properties` сейчас указан локальный путь к JBR 21 Android Studio: `C:/Program Files/Android/Android Studio/jbr`. Проверьте его на своей машине и настройте `ANDROID_HOME` или игнорируемый `android/local.properties` с `sdk.dir`. Установленная в системе Java 25 не должна подменять JBR 21 для Android-сборки.
5. Для Android Google Sign-In зарегистрируйте Android-приложение с package name `app.mindes` в том же Firebase-проекте. Возьмите актуальный `google-services.json` в **Project settings → General → Your apps → Android app** и положите в `android/app/` (путь игнорируется Git). Добавьте SHA-1 для используемой debug- и/или release-подписи в настройках Android-приложения Firebase. После настройки Google Sign-In скачайте обновлённый JSON. Если меняете Firebase-проект или OAuth-клиент, сверьте `server_client_id` в `android/app/src/main/res/values/strings.xml`.
6. Для CLI-деплоя нужен вход `firebase login` и права на проект `mindes-15db2`. Для публикации Android нужны отдельные доступ к Google Play Console и release-ключ подписи; в репозитории нет настроенной release-подписи.

## Обычные команды

Из корня репозитория:

```powershell
npm ci
Copy-Item .env.example .env.local  # только при первичной настройке; заполнить значения
npm test                            # точечные проверки сохранения, дат и уведомлений
npm run dev                         # Vite, порт 5173
npm run build                       # сборка в dist/
npm run preview                     # проверка собранной веб-версии
npm run android:sync                # build + cap sync android
npx cap open android                # открыть подготовленный Android-проект
```

Для debug APK после `npm run android:sync`:

```powershell
cd android
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'  # для этой консоли; на другой машине скорректировать путь
.\gradlew.bat assembleDebug
```

Результат: `android/app/build/outputs/apk/debug/app-debug.apk`. Скрипт `npm run apk` делает сборку и синхронизацию в одном шаге; `npm run apk:install` требует работающий ADB и подключённое устройство. Перед Android-сборкой проверьте `.env.local` и `google-services.json`: отсутствие конфигурации не обязательно останавливает компиляцию, но приложение не сможет нормально использовать Firebase. После любого изменения веб-кода повторяйте `cap sync android` перед проверкой APK.

## Правила изменений

- Сохраняйте структуру Firestore и существующие поля дерева. У узла есть `id`, `text`, `done`, `description`, `checklist`, `children`; дополнительно используются `archived`, `priority`, `deadline` (ISO), `repeat`, `remindBefore`, `colorIdx`. В каждом проекте корневой узел имеет `id: "root"`. Изменение формата уже сохранённых документов требует миграции или обратной совместимости.
- Изменения дерева делайте иммутабельно через `updateTree` из `useFirestoreSync` и функции `src/utils.js`. Запись целого дерева откладывается на 500 мс; проверяйте сценарии быстрой правки, удаления проекта, закрытия вкладки, офлайн-режима и изменений с двух устройств. Последняя запись целого документа может перезаписать параллельную правку; не обещайте бесконфликтную синхронизацию.
- В панели задачи название, описание, параметры напоминания и повтора сохраняются при вводе допустимого значения. Текст сохраняется без обрезания пробелов; полностью пустое название отклоняется. В окне проекта изменения применяются кнопкой «Сохранить», причём отправляются только изменённые поля; фон — кнопкой «Применить». Не возвращайте сохранение текстовых полей задачи только на `blur`: закрытие панели жестом, Escape или кнопкой «Назад» может размонтировать поле без этого события. При правке синхронизации сохраняйте локальные изменения поверх старых снимков Firestore до подтверждения соответствующего `clientWriteId`.
- Не обходите проверку `request.auth.uid == userId` в `firestore.rules`. Изменения правил проверяйте отдельно от UI и выкладывайте отдельным осознанным действием.
- При изменении маршрутов обновляйте обработку в `src/App.jsx`, переходы из экранов и проверяйте прямое открытие/обновление URL на Hosting и в PWA.
- Любое добавление или изменение текста, видимого пользователю, сопровождайте переводом на все доступные языки (`en`, `ru`, `zh`, `es`, `hi`, `pt`, `fr`, `kk`) в `src/i18n.jsx`. Это относится к кнопкам, карточкам-примерам, датам, заголовкам, подсказкам, ошибкам, уведомлениям и подписям установки PWA. Не оставляйте пользовательские строки захардкоженными в компонентах или функциях форматирования. Перед сдачей проверяйте полноту ключей переводов, переключение всех языков до и после входа, сохранение выбора после обновления страницы, мобильную ширину, обе темы и онбординг. Используйте существующие темы и общие компоненты до добавления новых стилей.
- При изменении кеширования PWA проверяйте онлайн/офлайн и обновление установленного приложения; при изменении схемы кеша меняйте версию `CACHE` в `public/sw.js`. Не кешируйте запросы Auth/Firestore.
- При изменении нативных плагинов или `capacitor.config.json` выполняйте `npm run android:sync`, проверяйте Android-сборку и требуемые разрешения. Не редактируйте файлы, помеченные Capacitor как generated, вручную без необходимости.
- Не коммитьте `.env.local`, `android/app/google-services.json`, локальные SDK-пути, release keystore, пароли, токены, `dist/`, `node_modules/` и результаты Android-сборки. Проверяйте `git status` перед коммитом.
- `public/` целиком попадает на открытый Firebase Hosting и в Android APK. Не кладите туда личные фотографии или другие закрытые файлы. Удаление из рабочей папки не удаляет файл из Git-истории, старых APK и уже опубликованного Hosting; при удалении проверяйте все эти места и кеш PWA. После изменения кеширования повышайте версию `CACHE` в `public/sw.js`.

## Проверка перед сдачей изменений

1. `npm ci` при чистой установке, `npm test` и `npm run build` после правок. Vite может успешно собрать приложение с пустой Firebase-конфигурацией, поэтому успешная сборка не подтверждает вход или синхронизацию.
2. С реальной тестовой учётной записью проверить Google-вход, создание/переименование/удаление проекта, вложенные задачи, чеклист, дедлайн и повтор, архив, смену темы/языка, фон, прямой переход по URL, обновление страницы и выход.
3. Проверить онлайн/офлайн и повторное подключение Firestore, две вкладки/два устройства, PWA после обновления и напоминания на нужной платформе. На вебе закрытая вкладка не выдаст напоминание.
4. Для Android после `npm run android:sync` собрать debug APK и проверить на устройстве вход Google, Firestore, кнопку «Назад» и локальные уведомления. Проверьте ADB через `adb devices`. Debug APK не является проверкой release-подписи или публикации.
5. `npm test` запускает точечные тесты из `tests/behavior.test.js`, включая быстрые последовательные правки и старые снимки синхронизации; полного покрытия UI, Firebase и Android нет. Также нет настроенных `lint`, CI и автоматического релиза. Имеющиеся Java `Example*Test` — шаблонные тесты Capacitor, не проверяющие функции Mindes.

## Деплой

**Web:** проверьте `.env.local`, затем `npm run build`, `npm run preview` и нужные пользовательские сценарии. После проверки целевого проекта и разрешения на публикацию выполните `firebase deploy --only hosting --project mindes-15db2`. Скрипт `npm run deploy` тоже публикует live Hosting и берёт проект по умолчанию из `.firebaserc`; не запускайте его как проверочную команду. Preview-канал можно создать через `firebase hosting:channel:deploy <channel> --project mindes-15db2`; при текущем `.env.local` он всё равно работает с тем же Firebase Auth/Firestore, поэтому проверяйте на тестовой учётной записи.

**Firestore:** `firebase.json` включает `firestore.rules` и `firestore.indexes.json`, но `--only hosting` их не выкладывает. После проверки правил отдельно выполните `firebase deploy --only firestore --project mindes-15db2`; эта операция заменяет правила/индексы целевого проекта согласно файлам репозитория.

**Android:** подготовьте `.env.local` и `google-services.json`, выполните `npm run android:sync`, соберите и проверьте debug APK. Для релиза настройте release signing, сохраните ключ и пароли вне Git, увеличьте `versionCode`/`versionName` в `android/app/build.gradle`, соберите подписанный AAB и протестируйте внутренний трек Google Play перед публикацией. В текущем репозитории нет готового процесса подписанного релиза.

## Известные ограничения репозитория

- README говорит о web push; фактически браузерные уведомления зависят от открытой вкладки. Не описывайте их как фоновые push-уведомления.
- Все задачи одного проекта хранятся одним документом Firestore. При росте дерева учитывайте размер документа и конфликтующие записи с разных устройств.
- Карточки проектов и задач сокращают длинный текст визуально ради компактного списка; полное значение должно сохраняться в Firestore и быть доступно в окне редактирования. Не путайте такое отображение с потерей данных.
- `.firebaserc` указывает на боевой проект; отдельное тестовое окружение и эмуляторы Firebase не настроены.
- `android/gradle.properties` содержит машинозависимый путь к JBR 21. На другом компьютере путь нужно проверить; Gradle 8.5 поддерживает Java 21, но не Java 25 как среду запуска.
- Два транзитивных пакета Firebase закреплены через `overrides` в `package.json` на исправленных версиях. На 23.10.2026 `npm audit --omit=dev` не сообщает об уязвимостях; полный `npm audit` сообщает о четырёх находках в инструментах сборки Capacitor CLI и Vite. Их автоматическое исправление требует перехода на новые основные версии. Не применяйте `npm audit fix --force` без проверки совместимости Capacitor и Firebase; перед релизом повторите аудит.
- Vite настроен с `server.host: true`, а `npm run preview` использует `--host`; при запуске они могут быть доступны другим устройствам в локальной сети. Используйте доверенную сеть или явно задавайте `--host 127.0.0.1`, когда внешний доступ не нужен.
